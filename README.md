## なぜ作ったか

手続きのことを調べようとすると、広告とアフィリエイト記事とランキングに埋もれて、肝心のことが読めません。
とくに、当事者がいちばんつらい時期にしか必要にならないページほど、そうなっています。

知りたいのはたいてい2つだけです。**いま何をすればいいのか。いつまでなのか。**
それだけを、スマホの1画面で追えるようにしました。

## それぞれの中身

**おくやみノート** — 亡くなった日を入れると、いま何日目で次にどの期限が来るのかが出ます。
9段階、34項目。**令和6年4月1日より前に相続したまま登記していない不動産は令和9年3月31日が期限**
（相続登記の申請義務化の経過措置）という、いま効く話も入れてあります。

**介護のノート** — 申請した日を入れると、認定通知の目安（原則30日以内）が出ます。
認定の有効期間の終了日も別枠で入れられます。介護休業の「要介護状態」に
**介護保険の要介護認定は要らない**こと、介護休暇が**通院の付添いや手続代行にも使える**こと、
令和7年4月1日から**会社側に個別周知・意向確認の義務**ができたことを書いています。

**退職のノート** — 退職日を入れると期限が並びます（退職前の未来日も入ります）。
自己都合の給付制限は**令和7年4月1日以降の離職から原則1か月**で、
古い記事の「2か月」「3か月」が残っている論点なので厚労省で直接確認しました。

**確定申告ノート** — A 会社員の還付申告／B 副業・雑所得／C フリーランス に分岐。
期限は今日の日付から自動計算し、3月15日が土日の年は翌平日に繰り延べます。
**「20万円以下なら申告不要」は所得税の話で、住民税の申告は必要**という点を分けて書いています。

**防災の備蓄ノート** — 家族構成と日数を入れると必要量が出ます
（水、主食、カセットボンベ、非常用トイレ、液体ミルク、ペット）。
買ったものを登録すると、期限が近い順に並んで入れ替え時期がわかります。

**引っ越しノート** — 引っ越す日を入れると、前の期限（解約予告、ネット回線、転出届）と
後の期限（転入届14日、児童手当15日、犬30日）が同じ列に並びます。
**転出届は「あらかじめ」で条文に日数の定めがない**（住民基本台帳法24条）など、
よくある誤記を条文まで当たって直してあります。

## この一連のノートの決めごと

**制度や基準は、必ず一次情報で裏を取る。**
金額、期限、手数料、対象になる人は、法務省・国税庁・日本年金機構・厚生労働省・裁判所・法務局・
e-Gov法令検索で確認したうえで書き、その項目に出典リンクを置いています。
制度の情報は、記憶で書くと必ず古くなります。

**どこが裏の取れた数字で、どこが提案なのかを分ける。**
出典を付けられる制度・基準と、付けられない一般的な段取りのコツを、ページの中ではっきり区別しています。
読む人が信じる範囲を自分で決められるようにするためです。

**自治体や加入先で変わるものは、断定しない。**
窓口の名前、葬祭費の額、持ちものは、地域や保険者で変わります。
そこは数字を書かず、「どこに聞けばいいか」だけを書いています。

**入力したものは、その端末から出ない。**
日付もチェックの状態も、ブラウザの中（localStorage）にだけ保存されます。
サーバーには送られず、他の人にも見えません。アクセス解析も広告も入れていません。

## 気をつけてほしいこと

ここに書いてあるのは**一般的な流れと、法令で決まっている期限**です。
実際に必要な手続きは、その人が何に加入していたか、不動産や事業があるか、
家族が何人いるかで変わります。

**期限の起算点は手続きごとに違います。**「その日から」「知った日から」「その翌日から」
「あらかじめ」「速やかに」。ページ内ではそれぞれの正式な起算点で書いていますが、
**実際の期限は、窓口・専門家の案内を優先してください。**

相続で話がまとまらない、借金がありそう、不動産が複数ある、税がかかりそう、
会社とのやりとりでもめている——このどれかに当てはまるなら、
早めに弁護士・司法書士・税理士・社会保険労務士に相談したほうが、結果的に安く済むことが多いです。

## 作りかた

```
src/            ソース（<title> から始まる body 断片）
  _base.css       全ノート共通のスタイル（各ソースの %%CSS%% に差し込まれる）
  index.html      索引
  okuyami.html    おくやみノート
  kaigo.html      介護のノート
  taishoku.html   退職のノート
  kakutei.html    確定申告ノート
  bousai.html     防災の備蓄ノート
  hikkoshi.html   引っ越しノート
build.js        docs/ と dist/ を生成する
docs/           GitHub Pages で公開する形（これが本命）
dist/           1ファイルで渡す形（.gitignore 済み）
```

```sh
node build.js
```

新しいノートを足すときは、`src/` にソースを置いて `build.js` の `NOTES` に1つ足すだけです。
`ready: false` のままなら、索引に「準備中」として出るだけでページは作られません。

ソースの中で使えるプレースホルダ：

| | |
|---|---|
| `%%CSS%%` | `src/_base.css` が差し込まれる。`<style>` の先頭に置く |
| `%%HOME%%` | 索引への行き先。docs では `../`、dist では `くらしのノート.html` |
| `%%NOTE:slug%%` | ほかのノートへの行き先。docs では `../<slug>/`、dist ではファイル名 |

出力先ごとに行き先が違うので、ノート間リンクをベタ書きすると dist 側が必ず壊れます。
